# Fault injections on the Embeat evaluation

The original v4 gate blocked the known reject planted at rank 1, and the verifier caught a broken pool-row join. The verifier accepted a label swap, a forged challenger score, a flipped Embeat weight and a changed catalog feature. The flipped weight still qualified for a blind trial. These are results from running the checked-in scoring and decision code on disposable inputs. The real stage-4 judgment and catalog files were unavailable for this replay.

## Mutation matrix

The synthetic control supplied 32 training likes, 8 training rejects and 17 catalog rows, one of which is a training alias. Of the 16 eligible catalog recordings, 10 had synthetic likes, 2 synthetic rejects and 4 no judgment. The control reached `ELIGIBLE_FOR_BLIND` with challenger P@10 1.00, NDCG@10 1.0000 and the rejects at ranks 15 and 16. No listener rated these fixtures.

A second gate discrepancy appeared in isolation. On the clean fixture, reversing only sample 42's NDCG delta versus v6 produced `NO_GO_OFFLINE` in the runner and `ELIGIBLE_FOR_BLIND` in the checker. The runner's sign check covers P@10 and NDCG at `integrate_v4.py:108`. The original check at `check_v4.py:160` covered only P@10. The checker now independently enforces both. This is a decision-function test with controlled metric inputs. It makes no claim about a particular real fold.

**P0 — claimed live keeps were independent of the raw rating file.** The runner reads a JSON array from the `live` source and copies it into `live_rounds` (`integrate_v4.py:173` and `integrate_v4.py:394`). The original verifier recounts the report's answer key and Boolean answers (`check_v4.py:190` and `check_v4.py:219`). A synthetic balanced four-record deck supplied two challenger keeps in the report while a separately locked raw live file contained `[]`. The reviewer reproduced strict acceptance, and the new test first failed with `ValueError not raised`. Such a discrepancy at a checkpoint could corrupt a promotion decision. The repaired strict checker requires a declared live source for reported rounds and compares the complete rated array, including JSON types. It rejects the empty file, a missing declaration and integer `1` in place of Boolean `true`. It accepts the exact rated file. An in-memory or explicit structure-only replay can still recount internal arithmetic. The two synthetic keeps do not reach a live decision checkpoint.

## Reproduce

These commands run the same tests first against the pinned pre-fix code and then against the working revision. The temporary directory contains only Python files. All generated JSON files are disposable and local.

```bash
old=$(mktemp -d)
git archive 463331ccaed9ab5f3b8d1c9703bff956b155f566 -- '*.py' | tar -x -C "$old"
cp test_audit_mutations.py "$old/"
(cd "$old" && OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python -m unittest -v test_audit_mutations)
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python -m unittest -v test_audit_mutations test_check_v4 test_integrate_v4 test_evaluate_v4
```

Before fixing the checker, the first run of seven cases failed on four expected assertions. Three corrupted records produced `ValueError not raised`, and the sampled-NDCG assertion returned `ELIGIBLE_FOR_BLIND`. The eligible baseline, rank-1 policy veto and pool-row join passed. A separate pre-fix checker run of the forged rank-1 case accepted the score as an internally consistent report. The first cross-directory CLI run also failed because the producer recorded relative source paths. The runner now records resolved paths for its local audit. The final pinned-code replay ran 13 mutation and control tests, with 9 failures and 4 passes. The repaired revision passed all 37 mutation and pre-existing v4 tests with Python 3.12.14, NumPy 2.3.5, SciPy 1.17.0 and scikit-learn 1.8.0.

## What can be verified

`python check_v4.py RUN.json` checks the declared raw files, channel scoring, ranking, arithmetic and decisions for a new local run. `python check_v4.py RUN.json --source-lock TRUSTED.json` also accepts a separately retained JSON object mapping source roles such as `fresh` or `catalog` to their pre-run SHA-256 digests. A lock generated from a changed file after the run adds no independent evidence. An old audit without the channel trace can still be inspected with `--structure-only`. That mode checks structure and arithmetic only. The normal CLI rejects a scored audit stripped of its source declarations or channel trace and rejects an attempted promoted verdict masquerading as a missing-input run.

Source files establish which labels entered a run. Only the original rating record can establish whether those labels reflected the listener's judgment. Channel replay verifies the two Embeat blends conditional on the emitted channel membership and order. The experiment does not replay acoustic feature extraction, learn the v2 model independently, authenticate that a blind deck was issued, or establish live preferences. Existing historical output can support checks only at the level of the evidence it retained.
